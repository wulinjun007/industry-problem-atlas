# 行业问题地图 · Industry Problem Atlas

把重庆「33618」18 个新星产业逐个还原成「行业问题地图」：**谁**在什么情况下遇到**什么问题**，现在**怎么处理**，为什么难，哪些步骤**值得数字化**。

> 完成标准：一个不了解该行业的人，仅看这份文档，就能回答以上四个问题。

**线上地址**
- Netlify（主站）：<https://industry-problem-atlas.netlify.app>
- GitHub Pages（备份）：<https://wulinjun007.github.io/industry-problem-atlas/>

## 站点内容

- **18 张问题地图**（`industries/*.html`，数据在 `data/industries/*.json`）
- 每张地图包含：产业链地图（上中下游）· 用户角色地图（5~9 类）· **22~24 个真实工作场景**（触发事件 / 当前做法 / 所需输入 / 决策参数 / 痛点 / 频率 / 痛感 1~5 / 错误成本 / 现有替代 / 搜索关键词 / 网站可解性 / 证据强度）· 现有产品与工具及缺口 · 真实公开案例 · 重庆本地锚点 · 网站可解 vs 必须线下 · 产品形态与 MVP 闭环 · 访谈对象 / 访谈问题 / 验证指标
- 全站合计 **407 个场景、142 类角色、149 个现有工具、82 个公开案例**
- **八大底层问题汇总**（首页「八大底层问题」区块，数据在 `data/archetypes.json`）：18 个产业的痛点归为 8 种稳定的企业问题（不知道选什么 / 值不值得做 / 下一步怎么走 / 谁能提供能力 / 文档太分散 / 能否商用 / 供需互相找不到 / 证据与宣传难区分），每种挂产业成员与对应网站形态——用于从地图里选 1~3 个值得产品化的问题
- **方法论页**：八层问题坐标系（研究陌生行业的分析顺序）· 21 项固定拆解深度 · 证据分层 · 网站可解性三判定（+网站能缩短的 7 种成本 vs 不硬碰的线下环节）· 产物正确顺序（先地图 → 选 1~3 个问题 → 再需求文档）

## 诚实边界

- 所有痛点、频率、痛感均为**有产业依据的问题假设**，不是已验证的用户需求；每条场景标注证据强度（高/中/低）。
- 案例只收录公开广为人知的事实；不编造数字、论文与链接。
- 数据契约见 [`data/CONTRACT.md`](data/CONTRACT.md)；用 `node build.js` 重建全站；`node tools/validate.js <num>` 校验单产业数据。

## 构建

```bash
node build.js                 # data/industries/*.json → 根目录 HTML
node tools/validate.js 01     # 校验单个产业数据（PASS 才算完成）
```

纯静态站，无框架无依赖（构建脚本用 Node 标准库）。

## 生成过程说明（存档）
