动力装备

智能装备

核心问题动力装备的故障预测与远程运维为什么落地难，后市场服务如何数字化

这个产业卖一台机器只是开始，备件、维保、大修要吃二三十年：设计工程师在台架上磨工况点，售后工程师在客户现场等件找原因，事卡在故障预测没人信、存量机组数据拿不到、停产机型找根曲轴要打一天电话。

细分方向内燃机/增程器发电机组压缩机风电水电配套船用动力
典型用户整机设计工程师试验测试工程师售后服务工程师备件采购终端运营方
重庆锚点华电潼南我国首台 550 兆瓦 F 级重型燃机 2026 年全容量投产，燃机核心热部件自主化是公认短板博世氢动力在渝布局 300kW 氢燃料电池系统；潍柴江津基地规划年产 5000 套氢燃料电池青山工业深耕传动系统，九龙坡/璧山是动力传动配套承载区重庆康明斯大马力柴油机长期配套发电机组与工程机械，重庆有整机与配套的存量服务市场

产业核心为车辆、船舶、电站与工厂提供动力和能量转换装备——内燃机/增程器、发电机组、压缩机、风电水电与船用动力配套，赚整机销售与后市场（备件、维保、大修）长尾的钱。

S01

数据中心柴发备用电源选型与台数配置

终端运营方
触发事件

新数据中心扩建，总包要求两周内提交柴发配置方案（N+1 还是 2N、机组台数与单机功率）

当前做法

找 3 家机组厂商销售各出一版方案 → 每家对市电切换时间、突加负载率、海拔温度修正的算法都不同 → 评审会上各说各话，最后靠品牌信任拍板

所需数据

负载清单、市电容量、机房布局、适用标准（GB/T 2820 或 ISO 8528）、各家方案书

决策参数

备用功率与常用功率之别、突加负载能力、ATS 切换时间、并机性能、占地与噪音限值

具体痛点

同一份负载清单能算出 6 台和 8 台两种结果；有厂商把「备用功率」当「常用功率」宣传，买方很难在评审现场拆穿

错误成本

配置不足真停电时顶不住；配置过度则每年多付占地、油耗与维护费

现有替代

设计院出图（排队且不细到机型）+ 厂商销售口头承诺

季网站可解证据高
柴油发电机组选型备用功率N+1 冗余突加负载ISO 8528
🖥 机组参数库 + 在线选型计算器：输入负载曲线与冗余策略，输出满足突加负载率的台数方案与逐台校核，每个参数附测试条件原文
S02

为新能源重卡平台匹配增程器工作点

整机设计工程师
触发事件

车企发来增程器定点询价，要求 8 周内提交发电 MAP、NVH 与布置可行性方案

当前做法

从现有机型谱系挑基础机 → 重新标定发电工况点测 MAP → 出多版油耗/噪声权衡方案 → 车企改了整车工况谱，推倒重来一轮

所需数据

整车工况谱与功率需求、基础机 MAP 数据、NVH 实测、布置边界

决策参数

高效区覆盖率、额定发电点油耗、启动噪音、轴向尺寸与悬置方案

具体痛点

各家 MAP 图测试条件不一致没法直接比；车企每次改工况谱，高效区匹配就要重测一轮台架

错误成本

定点丢失即五年生命周期出局；匹配错高效区，上市后油耗超标有召回风险

现有替代

靠既有客户关系与低价入围，匹配细节投标后再谈

季部分可解证据中
增程器MAP 图高效区匹配定点NVH
🖥 机型谱系参数库（附工况点与测试条件）加 MAP 对比工具帮快速初筛；最终定点与台架实测仍要线下
S03

耐久试验排期爆满，找第三方台架空档

试验测试工程师
触发事件

客户投诉引发紧急验证任务，自有台架已被新项目耐久占满两个月

当前做法

打听哪些第三方试验中心有空档 → 逐家打电话问排期与工时价 → 拿不到对方设备能力与已做标准清单，担心测了不被客户认可

所需数据

试验标准（如 GB/T 19055）、样机尺寸重量、工期窗口

决策参数

台架功率覆盖、测功器型号、采集通道数、报告资质认可度、工时单价

具体痛点

第三方台架的设备清单、排期空档、价格全靠电话问；急单找不到台架就拖整个项目节点

错误成本

验证延迟，整改量产节点顺延，违约金按天算

现有替代

自建台架（千万级投入）或排队等自家台架

月网站可解证据中
发动机台架试验第三方检测可靠性试验排期GB/T 19055
🖥 台架资源对接平台：按机型/标准/时间窗检索第三方台架空档与设备能力档案，在线询价锁期
S04

500 小时耐久后的拆检与磨损评级

试验测试工程师
触发事件

增程器 500h 台架耐久跑完，要拆机判定缸套轴瓦磨损是否超标，出报告给车企

当前做法

吊下整机 → 按工序拆解 → 量具逐件测量并拍照 → 对照内部评级标准打分 → 争议件由老师傅目视复核

所需数据

拆检规程、量具与三坐标、试验油样、同型号基准件

决策参数

缸套磨损量、轴瓦目视等级、机油消耗率、各部位积碳与胶状物

具体痛点

磨损评级一半靠老师傅手感目视，各厂内部标准不一；拆检做完样机即报废，争议件无法复检

错误成本

评级偏松，带病状态流入量产；评级偏紧，误判设计问题错失定点

现有替代

送第三方拆检（费用高、周期一周起）

月必须线下证据高
耐久试验拆检磨损评级缸套磨损轴瓦机油消耗
⛔ 线下原因：拆解测量与磨损判定必须实物操作、专人复核——网站只能沉淀评级图例库与拆检规程模板
S05

排放公告切换窗口前的标定冲刺

标定工程师
触发事件

新机型要赶在排放公告切换窗口前拿到公告，否则当年不能开票销售

当前做法

白天抢台架跑工况点 → 夜里改喷油与 EGR 的 MAP → 每轮送排放实验室复测 → 一次不达标重来一轮

所需数据

排放循环（如 WHSC/WHTC）、标定变量表、上轮试验报告

决策参数

NOx 与颗粒物限值余量、油耗代价、后处理再生策略

具体痛点

排放实验室档期以周计、每轮复测数万元；公告窗口错过就是半年卖不了车

错误成本

错过公告窗口，渠道库存成废铁，季度回款落空

现有替代

外包给标定公司（报价高且有泄漏自家数据的顾虑）

季必须线下证据高
排放标定公告WHTCEGRDOC/DPF
⛔ 线下原因：标定闭环依赖真实台架、排放实验室档期与不可逆的公告窗口——网站只能整理限值速查与申报流程
S06

远程平台每天几百条告警，真假难辨

售后服务工程师
触发事件

早上打开远程运维平台，昨晚累积 300 多条告警，分布在几百台在保机组上

当前做法

按机型与告警等级人工排序 → 逐条点开看曲线 → 大多是传感器抖动、电瓶电压低这类噪声 → 凭经验标出三五条真隐患再打电话核实

所需数据

告警 ID、CAN 报文与曲线、机组运行历史、客户联系人

决策参数

告警触发阈值、持续时间条件、同型号历史故障率、故障后果等级

具体痛点

误报率高到客服和客户都不再信平台，真故障被淹没；阈值收紧会漏报、放宽会被淹死，没有跨机型的误报统计可参考

错误成本

漏掉一次真故障就是用户现场趴窝加品牌投诉；长期误报让客户干脆关闭数据回传

现有替代

Excel 人工台账 + 老师傅微信群里发截图问诊

日部分可解证据中
远程运维告警误报故障码CAN 报文预测性维护
🖥 网站沉淀跨品牌告警规则库（每条标注误报案例与建议阈值）；原始数据与预测模型仍须在自家平台内跑
S07

想上故障预测，客户不让数据出内网

售后服务工程师
触发事件

公司要在重点客户机组上推预测性维护，客户（电厂/化工）以网络安全为由要求内网隔离

当前做法

反复上门谈数据安全方案 → 客户只同意本地部署边缘盒子 → 单台机组数据量撑不起模型 → 最后退回「定期人工巡检+抄表」

所需数据

客户网络安全制度、机组品牌与协议开放性、可采集点位清单

决策参数

数据出网范围与脱敏方案、协议开放程度（J1939 自定义 PGN 是否公开）、单机样本量

具体痛点

大客户数据拿不到、中小客户没有数据；各品牌 CAN 报文含义不公开，跨品牌模型更无从谈起——这是故障预测落地难最硬的一堵墙

错误成本

预测项目停在 PPT 阶段，服务收入继续依赖人工巡检与坏后抢修

现有替代

在客户厂内部署边缘盒子，靠现场工程师每月拷数据

季必须线下证据中
预测性维护数据不出厂内网隔离J1939协议开放
⛔ 线下原因：数据边界靠商务谈判与现场网络改造确定——网站只能做各品牌协议开放性档案与数据合作协议模板
S08

停产机组深夜趴窝，全网找一根曲轴

备件采购
触发事件

干了三十年的老师傅退休，接手的年轻工程师在客户现场对着同款故障无从下手

当前做法

翻十年没更新的纸质服务手册 → 微信群里远程问其他区域老师傅 → 同一故障三个区域三种修法 → 最后凭试错猜中原因，过程没有留下任何记录

所需数据

故障码、症状描述、历史维修工单（分散在各系统）

决策参数

故障模式概率排序、检测顺序、专用工具与备件需求

具体痛点

排故经验以「人」为载体，工单系统里只有换了什么件、没有为什么；疑难故障的排查顺序没人写成可复用的决策树

错误成本

新人独立排故要熬数年；同一故障反复跑现场，服务成本失控

现有替代

内部培训课件（一年一版）与口传心授

哪些适合网站解决 以及哪些必须线下——诚实比乐观重要

🖥 适合网站解决

  • 找件与替代：备件件号替代关系库加货源聚合，把「打电话问一圈」变成「按件号一搜」
  • 选型与配置：柴发冗余配置、空压站组合、增程器工作点匹配的统一口径计算器
  • 故障知识：跨机型排故决策树与告警规则库，标注误报率与处置案例
  • 比价与口碑：维保报价拆解模板、服务商履约档案、副厂件口碑档案
  • 法规与认证：「机型×目标国」认证映射、排放改装方案与船级社认可流程导航
  • 二手与残值：机型档案（常见病/件源/大修市场价区间）与验机清单

🚧 必须线下 / 网站只能辅助

  • 拆检与失效分析：断口、金相、磨损评级必须实物检测与多方封样，责任界定在场下
  • 台架试验与排放标定：依赖真实台架、排放实验室档期与不可逆的公告窗口
  • 数据出网谈判与网络改造：电力/化工/船东的内网边界靠商务谈判与现场施工确定
  • 大修与热部件更换：吊装窗口、放行判定、原厂仲裁都在现场与合同里
  • 应急抢修：深夜趴窝的恢复靠人与件同时在现场，网站最多提前备好资料与货源

可做形态与 MVP 闭环 用户来 → 用什么 → 留下什么 → 如何变好

售后工程师与备件采购带着「这台机器怎么修、件在哪」来 → 按件号/故障码查替代库与决策树 → 得到处置路径与货源 → 处置完回填案例与货源信息 → 案例与货源越攒越多，新工程师独立排故周期缩短，服务管理者把它当培训教材

需要建设的数据表
  • 备件替代对照库（原厂件号/替代件号/适用机型/替代关系/供应商）
  • 故障案例库（机型/故障码/现象/真因/处置步骤/耗时/备件清单）
  • 机组参数库（机型/功率/排放阶段/MAP 工况点/认证状态）
  • 远程告警规则库（告警 ID/触发条件/误报率/处置建议）
  • 服务商档案（资质/品牌授权/履约评价/投诉记录）
信任来源
  • 每条案例标注机型/故障码/真因/处置人区域与日期，附被采纳次数
  • 替代关系分三级标注：原厂文件确认/用户装机实测/存疑待验
  • 告警规则条目标注误报率与统计样本量，引用曲线可回放
  • 法规与认证条目附文号与生效日期，过期自动置灰
可做产品形态
备件替代关系与货源聚合工具站（按件号搜索，标注可信度）选型计算器矩阵：柴发冗余配置/空压站组合/增程器工作点匹配排故决策树与故障案例社区（处置后回填机制）维保招标口径模板 + 服务商履约档案库出口认证与排放改装导航站

访谈与验证 痛点是假设，访谈才是裁决

访谈对象
整机厂售后服务经理与一线服务工程师 3~5 人发电机组租赁商与数据中心动力运维负责人 2~3 人备件流通商（原厂渠道与副厂渠道）各 1~2 人整机厂试验中心台架负责人 1~2 人
验证指标
  • 急件找货耗时：从打电话找 1~3 天降到 2 小时内锁定货源
  • 决策树月检索量与回填率：目标月检索 100+ 次、处置后回填率 >10%
  • 新人独立排故周期：相对访谈基线的可量化缩短
  • 付费验证：至少 3 家服务商或终端用户为档案库/招标模板付费
访谈问题清单（12）
  1. 最近一次印象最深的停机抢修：什么机型、什么故障、从发现到恢复多久、卡在哪一步？
  2. 停产机型找件你现在按什么顺序打圈？一周遇到几次？最远找到过什么货源？
  3. 远程平台每天多少条告警？你们估的误报率多少？怎么筛、筛完谁负责跟？
  4. 有没有因为告警太多而漏掉真故障的经历？后果是什么？
  5. 客户不让数据出网的真实原因是什么？你们试过哪些折中（本地盒子/人工抄表）？
  6. 预测性维护服务你报过价吗？客户问了什么？最后为什么没签？
  7. 大修周期你们按小时、按年限还是按状态？和厂家最大的分歧是哪一次？
  8. 维保招标里最常扯皮的条款是哪几条？怎么写能少扯皮？
  9. 老师傅的经验现在存在哪里？新人独立排故平均要多久？
  10. 买过假件或劣质副厂件吗？怎么发现的？最后怎么处理的？
  11. 如果有个按件号查替代与货源的工具，你愿意按次付费还是包年？多少钱会嫌贵？
  12. 什么条件下你愿意把自己的排故案例贡献出来共享？
